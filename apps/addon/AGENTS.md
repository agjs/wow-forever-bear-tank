## Architecture

Data flows one way: **game events → State (cached) → selectors (pure) → rows → List widget**.

```
BearTankCodex/
├── BearTankCodex.toc          # load order; tests are never listed
├── Core/                      # framework: no game knowledge
│   ├── Namespace.lua          # ns.module(name), version
│   ├── Text.lua (+ .test)     # pure string/color/money helpers
│   ├── Scheduler.lua          # debounce: coalesce bursts of events
│   ├── Events.lua             # one event frame + internal pub/sub topics
│   └── Store.lua              # SavedVariables with defaults
├── Data/                      # GENERATED by tools/build-addon. Never edit by hand
├── Services/
│   ├── Api.lua                # the ONLY file that calls WoW game functions
│   └── State.lua              # cached reads, invalidated by events, emits topics
├── Features/<Feature>/
│   ├── <Feature>.selectors.lua        # pure: (ctx, data) -> rows / view model
│   ├── <Feature>.selectors.test.lua   # co-located tests
│   ├── <Feature>.utils.lua            # pure helpers (+ .test.lua), when needed
│   └── <Feature>.tab.lua              # registers the tab: label, topics, build(ctx)
├── UI/
│   ├── Widgets/List.lua       # renders rows into pooled frames
│   └── Window/Window.lua      # main frame, tab bar, scroll, re-render on topics
├── Commands/Slash.lua         # /btq
└── Init.lua                   # wiring on ADDON_LOADED / PLAYER_LOGIN
```

**Rules**

- **Pure first.** Selectors and utils never touch WoW globals. They receive a `ctx` (level, zone and lookup
  functions) and static data, and return plain tables. That's what makes them testable.
- **One adapter.** Every game function call lives in `Services/Api.lua`, guarded for missing APIs.
  Features never call `UnitLevel`, `C_QuestLog`, etc. directly.
- **Rows, not frames.** A tab returns an array of row specs (`{ kind = "line", text = ..., action = ... }`).
  Actions are data (`{ type = "waypoint", stop = ... }`), resolved by the window. Only `UI/` creates frames.
- **Modules.** Every file starts with `local _, ns = ...` and uses `ns.module("Feature.part")`. No globals
  except the SavedVariables table and slash command entries.
- **Generated data.** Content comes from `packages/guide-data` through `tools/build-addon`. Fix the data
  there, then rebuild. The website and the addon share that one source.

## Performance

- No `OnUpdate` handlers. Everything is event-driven.
- Bursty events (`QUEST_LOG_UPDATE`, `BAG_UPDATE_DELAYED`) are coalesced with `Scheduler.debounce`.
- `State` caches every read and drops the cache only for the event that changed it.
- Only the visible tab renders, and only while the window is shown. Frames are pooled and reused, never
  re-created per render.
- Hooks on Blizzard UI use `hooksecurefunc`, run after Blizzard, and never change text width. Color is applied
  with inline color codes, so nothing overflows.

## Testing

- Runner: `tools/test.lua`, a dependency-free `describe` / `it` / `expect` runner on LuaJIT.
- Tests live beside the module as `*.test.lua` and load addon files through `loadAddon({ ... })`, which passes
  `(addonName, ns)` exactly like the client does.
- Test behavior (rows produced for a given level, skill or bag), not frame internals.
- For anything touching game frames, add a mock in `tools/wow-mock.lua` and test against it.

## Code standards

1. Lua 5.1: no `goto`, no integer division `//`, no `utf8` library.
2. `local` everything; cache hot globals (`local ipairs = ipairs`) only in hot paths.
3. Names: `PascalCase` modules, `camelCase` functions and fields, `SCREAMING_SNAKE` constants.
4. Formatting: StyLua (2 spaces, 120 columns, double quotes).
5. UI copy: sentence case, plain language, explain every name (what it is, where, when). No shorthand.
6. Never print in loops. User-facing chat output goes through `Text.say`.

## Release

1. Bump `## Version` in the TOC and `ns.version` in `Core/Namespace.lua`.
2. `pnpm build:addon && pnpm test:addon` from the repo root.
3. Commit and push. The site deploy publishes the zip, `addon-version.txt` and `update.ps1`; the Windows
   updater installs any newer version on its own.
